# Non-Goals

These items are out of scope for the early product unless another product document changes them.

- **Not trying to replace all of VS Code:** Inlinr should become excellent at Markdown authoring for AI-driven development, not a universal editor for every workflow.
- **Not a standalone document collaboration platform:** shared cloud docs, multiplayer presence, and team workflows are not first-version priorities.
- **Not whole-repo autonomous editing:** the early product should not roam across many files or make broad changes without tight user scope.
- **Not every file type at once:** start with Markdown before expanding to code, rich text, or other formats.
- **Not a WYSIWYG-only editor:** a polished rendered view matters, but the underlying Markdown should remain visible, editable, and trustworthy.
- **Not hidden or auto-applied AI edits:** users should review changes before they become document state.
- **Not a giant content generator first:** large one-shot document drafting is secondary to targeted revision and refinement.
- **Not provider-specific UX lock-in:** the product can start simple, but its concepts should outlast a single model vendor.
