# Scenario Traceability Matrix

Speckit is the spec/planning source here, not executable BDD. Executable coverage comes from the Mocha suites.

| Product scenario | Spec | Executable tests | Monitoring scenarios | Alert posture |
|---|---|---|---|---|
| **1. Rendered Markdown preview** | Markdown viewer opening | - opens Markdown in the Inlinr viewer<br>- switches viewer state when another Markdown file opens<br>- keeps non-Markdown on the default editor path<br>- shows in-viewer error or fallback for unsupported render cases<br>- keeps Mermaid fallback inside the viewer<br>- validates rendered viewer state contract | - preview load: route to viewer -> render Markdown -> viewer usable<br>- render failure recovery: viewer remains active -> failure state visible -> document preserved | - page after **2 consecutive** synthetic preview failures<br>- non-paging when preview **failure rate > 5%** with **10+ samples**<br>- non-paging when `render_markdown` fails **3+ times** in 30m<br>- non-paging after **3 consecutive** render-failure recovery failures |
| **2. Sentence-level scoped rewrite** | Selection-scoped edit request; execute selection request | - opens one anchored popup from a valid rendered selection<br>- submits only after explicit submit<br>- keeps selection scoped to the intended range<br>- keeps request attached after a small document shift<br>- blocks unavailable execution without mutating the document<br>- validates selection support and anchor re-resolution rules | - popup flow: selection recognized -> popup shown -> scope accurate<br>- submit/review flow: request submitted -> pending visible -> review rendered inline<br>- apply flow: apply available -> targeted range mutates -> render refresh<br>- safe failure flow: failure visible -> review/apply blocked -> document preserved | - page after **2 consecutive** popup synthetic failures<br>- non-paging when popup scope-accuracy checkpoint fails **3+ times** in 30m<br>- page when submit/review **failure rate > 10%** with **10+ samples**<br>- non-paging when pending latency **p95 > 15000 ms** with **10+ samples**<br>- page immediately if failure handling does **not preserve the document** even once |
| **3. Lightweight formatting action** | Gap - no dedicated spec yet | - popup script includes quick **bold** action<br>- popup script includes quick **italic** action | Gap - no dedicated scenario | Gap |
| **4. Subsection expansion with structure preserved** | Selection-scoped edit request; execute selection request | - preserves one contiguous range across adjacent prose blocks<br>- supports contiguous bullet-item selections even when markers are omitted visually<br>- supports chapter-scale selections that start at a heading<br>- ignores out-of-range draft changes and keeps only the selected-range proposal<br>- applies only the intended Markdown range<br>- normalizes bounded replacement or deletion proposals | - popup flow: selection recognized -> popup shown -> scope accurate<br>- submit/review flow: request submitted -> pending visible -> review rendered inline<br>- apply flow: apply available -> targeted range mutates -> render refresh<br>- safe failure flow: failure visible -> review/apply blocked -> document preserved | - page after **2 consecutive** popup synthetic failures<br>- page when submit/review **failure rate > 10%** with **10+ samples**<br>- non-paging when review-rendered checkpoint fails **3+ times** in 30m<br>- page when apply **failure rate > 5%** with **10+ samples**<br>- page immediately if failure handling does **not preserve the document** even once |
| **5. Review, apply, or reject a scoped change** | Execute selection request | - shows pending feedback and one suggestion-ready proposal<br>- rejects a suggestion without mutating the document<br>- applies a suggestion only to the intended Markdown range<br>- applies deletion proposals only to the selected range<br>- removes the full containing list item when needed<br>- blocks apply and preserves recovery state when the target drifts<br>- validates rendered review-state contract | - apply flow: apply available -> targeted range mutates -> render refresh<br>- reject flow: reject available -> document unchanged -> review dismissed<br>- safe failure flow: failure visible -> review/apply blocked -> document preserved | - page when apply **failure rate > 5%** with **10+ samples**<br>- non-paging when `mutate_targeted_range` fails **2+ times** in 30m<br>- diagnostic-only after **3 consecutive** reject-flow failures<br>- non-paging when reject `document_unchanged` fails **2+ times** in 30m<br>- page immediately if failure handling does **not preserve the document** even once |
| **6. Iterate in the same session** | Execute selection request | - allows a new scoped request after reject in the same editor session<br>- allows a follow-up scoped request after apply against updated document state<br>- records next-request-cycle telemetry after the first cycle clears | - next request cycle: first cycle cleared -> fresh selection starts popup -> current state reused | - non-paging after **3 consecutive** synthetic failures<br>- diagnostic-only when `current_state_reused` fails **3+ times** in 30m |
| **7. Read rendered meaning and keep editing in one surface** | Markdown viewer opening; selection-scoped edit request; execute selection request | - renders Markdown in the custom viewer<br>- opens inline popup from rendered selection<br>- renders review inline in the document flow<br>- supports apply or reject without leaving the surface<br>- supports follow-up editing in the same session<br>- records end-to-end telemetry across preview, popup, review, and follow-up flows | - preview load<br>- popup flow<br>- submit/review flow<br>- next request cycle | - page after **2 consecutive** preview synthetic failures<br>- page after **2 consecutive** popup synthetic failures<br>- page when submit/review **failure rate > 10%** with **10+ samples**<br>- non-paging after **3 consecutive** next-cycle failures |
